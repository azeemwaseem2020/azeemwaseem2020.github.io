Permutation versus combination

Permutations count ordered arrangements, while combinations count selections where order does not matter. Choosing the correct model is more important than simply applying a formula.

Worked example

For n = 5 and r = 3, nPr = 5 × 4 × 3 = 60 ordered arrangements. The combination count is nCr = 5! ÷ (3! × 2!) = 10 groups. The permutation result is larger because changing the order creates a different arrangement.

How to choose the right method

Use permutations for ordered roles, rankings, codes or positions when order matters. Use combinations for selecting a group when only membership matters. If repeated choices are allowed or some items are identical, a different counting model may be needed.

Input limits and precision

Enter non-negative integers with r no greater than n. The calculator accepts n up to 170; exact integer results can be very large, so the implementation uses integer arithmetic to avoid ordinary floating-point rounding.

Frequently asked questions

Why is nCr usually no larger than nPr?

Each combination can be arranged in r! different orders, so nPr = nCr × r! when 0 ≤ r ≤ n.

What do 0 selected items mean?

There is one way to choose nothing from a set, so nC0 = 1. The empty arrangement also gives nP0 = 1 under the standard convention.

Does order matter for a team selection?

Usually not if the selected people simply form a team, so combinations are appropriate. If each person fills a distinct role, permutations may be appropriate.
